# PROVA v0.3.5-beta.2 — Phase 4 Controlled Beta

This beta packages the completed Phase 4 reliability and validation work for
controlled beta users. It keeps the existing CLI contract while adding a
repeatable, evidence-backed path through all eight release scenarios.

## Highlights

- One-command Phase 4 automation for Scenarios 1–8.
- Studio create, save, selector capture, and browser execution validation.
- Scenario 1 coverage across Chromium, Firefox, Edge, and Playwright WebKit.
- OpenAPI execution, performance regression, ZAP security, analytics, Android
  Appium, GitHub/Jira/Slack, and stale-selector repair validation.
- Strict pass/fail gating with combined HTML and JSON evidence reports.
- Encrypted local credential reuse with credentials and generated evidence
  excluded from Git.
- Studio preview URL hardening that rejects executable and malformed schemes.

## Validation

- Phase 4 combined automation: 8 passed, 0 failed.
- Scenario 1 multi-browser validation: Chromium, Firefox, Edge, and WebKit passed.
- Studio unit tests, production build, and CLI build passed.
- Pull request quality, coverage, secret-safety, LENS, and CodeQL gates passed.
- The high-severity iframe URL finding detected during review was fixed and
  independently cleared by the CodeQL security gate.

## Beta boundaries

- This is a controlled beta release, not a GA declaration.
- Jira, Slack, Appium, and other credentialed integrations require operators to
  configure their own local credentials or environments.
- Generated evidence can contain operational metadata and remains excluded from
  source control by default.

## Upgrade

```sh
npm install --global @provae2e/cli@beta
```

Existing `prova` and `qe-tool` binary aliases remain supported.
