## Evidence package contract

Every failed scenario directory contains:

- `screenshot.png` — final failure-state screenshot;
- `trace.zip` — Playwright trace for interactive diagnosis;
- `logs.json` — redacted browser logs;
- `metadata.json` — scenario, environment, duration, classification, and artifact index;
- `selectors.json` — attempted selector or API expectation;
- `failure.txt` — redacted failure message;
- `allure-result.json` — Allure-compatible result and attachment references.

An external team should start with `failure.txt` and `metadata.json`, inspect
`screenshot.png`, and open `trace.zip` with Playwright Trace Viewer. The target
is an actionable failure category within five minutes.

## Intentional-failure coverage

The campaign includes selector mismatch, ambiguity, timeout, assertion, REST
status, REST schema, API timeout, and GraphQL error scenarios. These are
expected failures: the CI job passes only when their failure evidence is
captured and validated.

## Secret-safety boundary

Sensitive object fields and known runtime secret values are replaced with
`[REDACTED]` before textual artifacts are written. The validator scans textual
artifacts for GitHub, OpenAI-style, Slack, AWS, Authorization, password, token,
API-key, and client-secret patterns. A planted-leak unit test proves the
scanner fails on a representative credential.

Binary screenshots and trace archives are generated only from the local,
non-secret diagnostic target. No live credentials are supplied to a page.
