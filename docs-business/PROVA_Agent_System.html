✅ What Is Fully Possible Right Now (June 2026)

Claude Code (claude.ai/code) runs as an autonomous agent in your terminal. It reads files, writes code, runs tests, executes git commands, and opens PRs on GitHub — all without human intervention per step. Agent Teams (experimental) lets one Claude orchestrate multiple subagents working in parallel git worktrees. GitHub Actions can trigger Claude Code automatically when an Issue is labeled. This pipeline — Issue → Agent → Code → Tests → PR → CI/CD — is proven and production-ready today.

⚠️ What Works But Needs Human Supervision

Complex architecture decisions still benefit from human review before the agent executes. Long autonomous runs (6+ hours) can drift. Ambiguous requirements cause agents to loop. Security-critical code should always have a human review gate before merge. The sweet spot is: you define the task clearly, agent implements and tests, you review the PR before merge. Not 100% autonomous — 90% autonomous, 10% human oversight.

✗ What Is NOT Possible Yet (Be Realistic)

Full zero-human autonomous deployment to production without any review is not safe or recommended. Agents cannot make good product decisions — they execute well-specified tasks. Novel architecture design (like building the PROVA knowledge graph from scratch) still needs human thinking first. Cost can spiral if agents loop without budget limits set. Cowork (desktop automation tool) is separate from Claude Code — it automates file/task management but is not a multi-agent coding system.

AGENTS.md — The Master Instruction File
# AGENTS.md — PROVA Engineering Standards # Every agent reads this before touching any code. ## Project Context PROVA is a CLI-first AI QE automation platform. Core: Node.js + TypeScript + Playwright + Ollama + SQLite. Release: bi-weekly to npm as @prova/cli. ## Agent Roles - ARIA: Read the GitHub Issue. Analyze the codebase. Plan the work. Delegate to FORGE (code) and VERA (tests) in parallel worktrees. Never write production code directly. - FORGE: Implement the feature. Follow TypeScript strict mode. File structure: src/[domain]/[feature].ts Never skip error handling. Always emit structured logs. - VERA: Write tests BEFORE marking work done. Test file: src/[domain]/[feature].test.ts Coverage minimum: 80% for new code. Run: npm test -- --testPathPattern=[feature] - LENS: Review every PR before it opens. Check: TypeScript errors, security (no hardcoded secrets), breaking changes, test coverage, architecture fit. - SHIP: Only runs after CI is green and human approves. Bump patch version. Write changelog entry. Publish npm. ## Non-Negotiable Rules 1. Never commit secrets, API keys, or passwords. 2. Never delete existing tests — only add new ones. 3. Never modify AGENTS.md without human approval. 4. All CLI commands must have --help documentation. 5. All new features must have a README section. 6. Tests must pass locally before opening a PR. ## File Boundaries — Agents Must NOT Touch - /src/core/knowledge-graph/ (architecture in progress) - /src/core/data-factory/ (human-owned for now) - package.json version field (SHIP agent only) ## PR Template Every PR must include: - What was built (1 paragraph) - Tests added (list) - Breaking changes (none / describe) - Related issue (#N)
